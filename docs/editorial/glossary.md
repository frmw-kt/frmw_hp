# 用語と表記の統一表（glossary）

複数の記事で同じ公式用語を同じように書くための表。並行執筆で記事同士の表現が食い違うのを防ぐ（2026-10-06、バッチ1の採点で導入）。
- 執筆者は着手時に読み、表にある語は表の書き方に合わせる。表にない公式用語を使ったら、完了報告の「用語の追加提案」に書く（並行執筆中はこのファイルを編集しない。統括が追記する）。
- 「避ける表記」の列の「」内の語句は `check:articles` が記事中にあれば警告する（括弧書きの説明は対象外）。**この列の「」には、そのまま記事に出てはいけない語句だけを書く**（説明のために語を引用する場合は「意味・使い方の注意」の列に書く。誤検出の原因になるため）。
- 画面の名称（UI名）は［］（全角）、「」は引用と強調に使う。半角の [ ] は使わない。［］で囲むのは、ボタン・メニュー・タブ・入力欄など公式ヘルプが [ ] で囲んでいる操作対象の名前。選択肢・チェックボックス・ラジオボタンの文言やステータスの名前（「所在地」「審査中」など）は「」で書く。

## 業態と「成果」「手前の段階」の基準
Metaの計測イベントと業態の対応表は、子記事 #27（meta-pixel-conversions-api）ができるまでは `meta-ads-how-to-start` の表を基準とし、他の記事は要約してリンクする（topic-map の線引き）。記事の主題に絞った表（例: meta-ads-small-budget の「手前の段階」だけの表）は持ってよいが、基準の表と食い違わないことを確かめ、基準の表へリンクする（2026-10-10）。基準の表を持つ記事（meta-ads-how-to-start）を直すときは、イベントの対応以外の列を変えた場合も完了報告に書く（統括が他の記事との食い違いを確認するため）。「問い合わせ」をどの段階として扱うかは業態で変わるので、表に業態を明記する。
