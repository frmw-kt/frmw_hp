- 各h2の1文目：
  1. Metaピクセルはブラウザから、コンバージョンAPIはサーバーから送る｜Metaピクセルはサイトに置くコードで、訪問者のブラウザから行動（イベント）をMetaに送り、コンバージョンAPIは自社のサーバーやCRM（顧客管理システム）からMetaに直接送ります。
  2. ベースコードの置き方は、サイトの作り方で3つから選ぶ｜Metaピクセルのベースコードは、使っているサイト構築サービスがパートナー連携に対応していればパートナー連携で、GTMを使っていればGTMのタグで、どちらでもなければサイトの全ページの<head>に直接貼って置きます。
  3. ピクセルはイベントマネージャで作り、全ページで動かす｜Metaピクセルは、イベントマネージャの［データをリンク］から作成し、作成後に表示されるベースコードを、パートナー連携・GTM・直接の貼り付けのいずれかでサイトの全ページに置きます。
  4. 問い合わせは、完了ページの表示で「リード」として記録する｜問い合わせ型の成果は、フォームの送信後に表示される完了ページ（サンクスページ）で、標準イベントの「リード」（Lead）として記録します。
  5. コンバージョンAPIは、開発者がいなければMeta対応かパートナー連携で始める｜コンバージョンAPIの設定方法は、Meta対応コンバージョンAPI、パートナー連携、コードを使ったダイレクト連携の3つで、Meta対応は無料でワンクリック、ダイレクト連携は開発者が必要で新規なら2〜4週間かかると、Metaは比べています。
  6. 同じイベントを両方から送るなら、イベントIDをそろえて重複を除く｜MetaピクセルとコンバージョンAPIの両方から同じイベント（例：リード）を送る場合は、ピクセルのeventIDとコンバージョンAPIのevent_id、ピクセルのイベント名とコンバージョンAPIのevent_nameを、それぞれ一致させて重複除外を設定します。
  7. 設定後は、テストイベント・診断・自社の件数の順で確かめる｜設定が終わったら、①ページビューが届くか、②成果のイベントが届くか、③コンバージョンAPIの分と重複除外、④［診断］タブの問題、⑤自社の問い合わせ件数との差、の順で確かめます。
  8. 照合の精度は、詳細マッチングとマッチングクオリティで確かめる｜Metaに届いたイベントがMetaのアカウントと照合される割合は、詳細マッチングでハッシュ化した顧客情報（メールアドレスなど）を一緒に送ると高まり、コンバージョンAPIで送ったウェブサイトのイベントでは、照合の効果を「イベントのマッチングクオリティ」の0〜10のスコアで確かめられます。
  9. 設置の前に、送ってはいけない情報と同意を確かめる｜MetaピクセルとコンバージョンAPIを設置する前に、①禁止されている情報を送らないか、②同意が必要な場面で取得しているか、③顧客に伝えているか、④自社のサイトか、の4点を確かめます。
  10. 業態で変わるのは、成果のイベントと記録できるページ｜成果のイベントは、問い合わせ型なら「リード」（電話・メール・チャットは「問い合わせ」）、予約・来店型なら「スケジュール」、EC型なら「購入」で、業態によって変わるのは、そのイベントを記録する完了ページを自社のサイトで用意できるかです。
  11. まとめ（対象外）｜完了ページの有無→［データをリンク］でパートナー連携の確認→［テストイベント］で「リード」→CAPIはMeta対応／パートナー連携→重複除外の表示→翌日以降［診断］、で締める
